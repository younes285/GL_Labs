## 3. XP pair reflection

The following is the self-review output, also preserved in
[docs/lab2-code-review.md](../docs/lab2-code-review.md):

1. **Error handling:** `BorrowingService` throws `EntityNotFoundException` and
   `IllegalStateException`, but no controller advice translates them. Missing
   records and unavailable books could surface as server errors. Map them to
   HTTP 404 and 409, preserving readable error details, and verify at API level.
2. **Edge case:** `returnBook` accepts an already returned loan. Returning an old
   loan after the same book has been borrowed again would incorrectly set the
   book available. Reject repeated returns before changing dates, fines, or book
   availability. Test this exact re-borrowing sequence.
3. **Coverage gaps:** service tests cover the happy paths, but the borrowing
   controller needs full request-flow coverage, missing-resource checks, invalid
   request checks, and assertions about state after rejected operations.
4. **Readability:** the fine rate is already a named decimal constant; give the
   14-day borrowing period a name too. Keep the fine calculator pure and reused
   by the return operation.
5. **Concurrency:** transactions make a single operation atomic, but two
   concurrent borrowers can both observe `available=true` without locking.
   Pessimistic locking or optimistic versioning needs a policy and a concurrency
   test before multi-user production use.
6. **XP practice:** each story had committed tests and an observed red phase
   before implementation. The red phases were compilation failures, which prove
   the required API was absent; they do not alone prove a test detects a wrong
   implementation. The final green assertions verify behavior. AI-generated
   tests still require human review, and these are assisted-session timings
   rather than a measured student-only velocity.

Suggestions 1 and 2 were applied because they fix observable API failures and
protect book availability. A borrowing-specific exception handler now returns
404/409 problem details, and `returnBook` rejects repeated returns before any
state changes. Suggestion 3 added five controller integration tests, including
the old-return-after-reborrowing regression; suggestion 4 named the loan period.
Suggestion 5 was deferred for this simulated single-user sprint: no locking
policy or concurrent-use acceptance criteria were specified. This is a limitation,
not a claim that transactional annotations prevent simultaneous double borrowing.

Codex acted as driver and self-reviewer; this does not replace the student's
independent review. The student's remaining task is to inspect the tests and
evaluate which assertions and review decisions they agree with.

## 4. AI and estimation

Under the proposed estimates, assisted technical execution took fewer hours than
expected: the ratio was 0.1203. This is not a controlled comparison with unaided
work, and it excludes personal learning, report writing and publication, so it
does not establish a student's productivity multiplier. Tool maturity helped
because the Java/Maven setup and dependency cache were already available from
Lab 1; a sandbox permission issue and occupied ports still added overhead.
For a similar second sprint, familiar tests and conventions could reduce setup
effort, but more complex requirements or additional human review could offset
that benefit. Personal study and review time should be measured separately.
